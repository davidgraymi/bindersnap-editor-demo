What if Bindersnap weren't coral?

Five palettes on the same Documents screen. The current warm-paper-and-coral system sits first as the control; four alternatives follow, each built on a different idea about what a document-custody product should feel like.

Only color changes. Type, spacing, radii and layout are held fixed at the values in packages/ui-tokens, so what you're comparing is hue alone.

Where each one lands

How the accessible values were produced. Each palette declares only intent hues. The page then solves, per theme, for the accent-as-text colour, the CTA fill that carries white at 4.5:1, and all four status foregrounds — walking lightness while holding hue and saturation until each clears AA against its own surface. Status backgrounds and borders are that solved foreground mixed into the card fill at 12% and 28%.

This is the same work the current token file does by hand in its comments — --bs-cta-fill, --bs-coral-text and the dark-mode status lifts all exist because raw brand coral fails as text. Any palette adopted here would need those solved values written back into the token file as literals, with the ratios asserted in tokens.test.ts.
