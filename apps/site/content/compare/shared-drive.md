Most small healthcare providers keep their policy manual in a shared drive: a network folder, Google Drive, Dropbox, OneDrive or a SharePoint site. It costs nothing extra, everyone knows how to use it, and for years it works well enough. Then a surveyor asks, "Who approved this version, and when?"

A shared drive is good at storing files. It isn't built to keep the **record around** each file. Here is where the difference shows up, and when a shared drive is genuinely enough.

## What a surveyor asks, and what each can show

| The question                                 | Shared drive or SharePoint                                                   | Bindersnap                                                                            |
| -------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Which version is current?                    | The file with the newest date, if nobody saved a copy elsewhere              | Exactly one version on record per policy                                              |
| Who approved it, and when?                   | An email, meeting minutes or a signature page, kept separately from the file | Recorded against that exact version                                                   |
| What did it say on the date of the incident? | Only if version history is on, kept long enough and never purged             | Every version, permanently                                                            |
| What changed in the last revision?           | Compare two files by eye                                                     | For policies written in Bindersnap, the change shown side by side, with its approvals |
| Was it reviewed on schedule?                 | A date typed in the footer                                                   | A dated approval of the current version                                               |
| Was a change approved before it took effect? | Only if everyone followed the process                                        | Yes: a change can't take effect until it's approved                                   |

## Can't SharePoint do this?

Some of it, with work. SharePoint document libraries have version history and can be set up with approval flows and retention rules. To make them hold up as a policy record, someone has to configure versioning limits, require check-out, build and maintain the approval flow, lock down who can edit published files, and make sure version history is never trimmed. That's a project, and it usually needs an IT person who stays.

If you have that person and the system is already running, it can work. Bindersnap is for the organizations that don't: the approval process, the permanent history and the one current version come built in.

## When a shared drive is enough

Be honest with yourself. A shared drive can be enough when:

- You have very few policies and one person writes and approves all of them.
- No surveyor, accreditor or payer reviews your policies.
- You keep approvals in a signed log that matches each file version, and you never overwrite a file.

If any of those stops being true, you're keeping the record by hand, and it will have gaps.

## Frequently asked questions

### Is a shared drive acceptable for policy management?

For storing policies, often yes. For proving which version was in force and who approved it, only if you keep a separate, complete approval record and never overwrite files. Surveyors ask for both.

### Does SharePoint have version control for policies?

SharePoint libraries keep version history and can run approval flows, if they are configured and maintained to do so. Check how many versions your library keeps and who can edit published files.

### Can we keep our files in Word?

Yes. Upload Word and PDF files to Bindersnap and edit them in Word as before, uploading each revision as a new version. Or write new policies in Bindersnap's editor.
