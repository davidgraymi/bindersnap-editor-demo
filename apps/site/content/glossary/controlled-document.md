A **controlled document** is a document whose versions, approvals and distribution are managed, so that the people who use it always have the current approved version, and earlier versions are kept but can't be mistaken for it. In healthcare, policies, procedures, plans and laboratory procedures are typically controlled documents.

## What "controlled" means in practice

A document is controlled when:

1. **It has an owner and named approvers.**
2. **It changes only through approval.** A revision has no effect until it is approved.
3. **There is one current version**, and that's the one staff can read.
4. **Earlier versions are kept**, with the dates each was in effect, and marked as superseded.
5. **Printed copies are uncontrolled.** A paper copy is only good until the next revision, so it must be checked against the current version before use.

Some rules spell this out. CLIA requires laboratory procedures, and every change to them, to be "approved, signed, and dated by the current laboratory director before use," and requires the laboratory to keep each procedure with its dates of initial use and discontinuance ([42 CFR 493.1251](https://www.ecfr.gov/current/title-42/section-493.1251)).

## Controlled documents in a shared drive

A shared drive makes control hard. Anyone with edit access can change the current file, copies multiply, and approvals live somewhere else. See [policy software vs. a shared drive](/compare/shared-drive).

Bindersnap treats every document in a binder as controlled: one version on record, changes only through approval, and every earlier version kept with its approvals.
